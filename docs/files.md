# Angelo — file map

- `plugin/src/code.ts` — RPC (`ping` / `selection` / `read` / `expand` / `exec` / `apply`), session, selectionchange
- `plugin/src/cursor.ts` — the live cursor (`H.cursor`, `H.pause`), labelled with the agent name: live progress, removed at the end of an exec · resumes from the last position of the previous exec (stays near its area), aims at the center / start of a text, `c.to(node, maxMs)`
- `plugin/src/autocursor.ts` — automatic cursor, created on the first write (nothing on a read) · ≤ 12 nodes = precise (glides and rests on each), beyond = volume (40 ms hops, the ring follows) · `apply`: `visit(target)` before each op (glide + 70 ms rest, the ring jumps beyond 3 s) · `exec`: the page's `nodechange`, pure geometry changes (hug / fill reflow) ignored unless they are all there is, last 10 nodes, drained within 2 s · events are delivered in batches ~100 ms after the write → 150 ms wait at the end of an exec · `H.cursor()` removes it (the script drives) · **plugin timers are throttled to ~1 s** (`setTimeout(16)` measured at 1000 ms, Figma in the foreground included) → the closing pass costs 1–6 s per exec: `quiet` exec (`runExec(code, file, quiet)`, `makeRpc(file, { quiet: true })`) = no cursor and no wait, for tools that run many small execs (`web-fix`, `web-compare`: 2000 → 5 ms per exec)
- `plugin/src/icons.ts` — embedded Lucide (`H.icon(name)`, 2313 drawings from `lucide-static`, JSON table generated by `plugin/build.mjs`, parsed on first call): the component `Icon / <name>` is looked up on the "lucide" page, else created in the `Lucide on demand` frame · 1 frame of 24 px + 1 filled vector (outline converted to a vector, follows resizing) · 25–33 ms to create, 0–1 ms afterwards
- `plugin/src/adapt.ts` + `adapt-rules.mjs` — `H.adapt(node, { dry, grid })`, `H.brand()`: a frame coming from elsewhere takes the file's colors, texts and grid (variables > styles > values in use), in place · the shared main is never modified (overrides on instances) · contrast kept against the background · `npm run adapt-check` outside Figma · `web-to-figma` calls it through `adaptToFile` (`tools/web-lib.mjs`) if `H.brand().ruled`: ≥ 4 colors or ≥ 3 named texts (variables, styles, a library seen in use) · the file's components are not reused yet
- `plugin/src/lint.ts` + `lint-rules.mjs` — `H.lint(node?, { rule, limit })`: components measured against the rules of `figma-structured-build` (3956 nodes in 139 ms) · same rules outside Figma: `npm run web-lint` (`tools/web-lint.mjs`) · in-place renaming: `tools/web-rename.mjs`
- `plugin/src/exec.ts` — executor ported from figma-local: `H` helpers, `toJSONSafe`, `locate` (`USER_LINE_OFFSET=3`, tied to the `new Function` wrapper), `commitUndo` before / after, `file` lock · the response is returned as soon as the script ends, the closing (cursor pass, `commitUndo`) runs in the background, any following request except `ping` / `selection` waits for it (`settled()`)
- `plugin/src/serialize/` — `format` (primitives) · `legend` (short names) · `node` (surface / detail, variable labels on `pad` / `r` rather than the resolved value) · `tree` (walk, chunks, yield) · `manifest` (shared) · `addendum` (late legend) · `rev` (per-node fingerprint, `revOf` is **async**: `getMainComponentAsync` is required in `dynamic-page`)
- `plugin/src/write/` — `apply` (the 5 ops in 2 passes: everything is checked before the first write; `each` filters the fingerprint table, each target goes through the same guard as a single op) · `props` (36 writable keys, `unquote`, auto-layout guard, `setNumber` binds / unbinds variables, `ref` / `ov` for instances)
- `tools/web-run.mjs` (`runBuild`, pure engine: its execs go through an injected `rpc`) · `web-place.mjs` (image placement) · `web-sha1.mjs` · `web-build.mjs` = the Node host (72 lines) · `plugin/src/web-core.mjs` = the `WebCore` bundle of that engine, inlined into `dist/ui.html` by `plugin/build.mjs`
- `plugin/src/web-images.mjs` — `dataImages`: images of a capture with no network and no sips (data URLs only, WebP / AVIF and oversized ones re-encoded through canvas), same contract and limits as `fetchImages`
- `plugin/src/ui.html` — `buildFile`: a `.angelo.json` file (button or drag-and-drop) built inside the iframe, execs sent to the main thread as `local-N`, no bridge, then Lucide icons (`tools/web-icons-run.mjs`, Node host `web-icons.mjs`) and adaptation to the file (`tools/web-finish.mjs`) · outside the plugin by nature: site fonts and late replacement (the plugin API does not activate fonts → the status names the families that fell back), `web-compare --fix` (python + page.jpg; the extension provides no reference view → the status gives images placed / total), `swapSections` (`--part`, absent from file captures), pasting a URL without a bridge (origin `null`, no render → message pointing to the extension)
- `extension/` — bridge unreachable → the capture is saved as `<site>.angelo.json`, images attached as data URLs (service worker fetch, hence `<all_urls>`, 6 in parallel, 30 MB max per image), no reference view
- `bridge/src/server.mjs` — HTTP `/health` `/rpc` + WS `/plugin` · every successful web-to-figma build (extension, panel, pasted URL) puts its frame (`frame <id> in Figma`) in the `toCorrect` queue → `onCheck` (`tools/web-fix.mjs`: deterministic fixer ~0.5 s then web-compare `--fix`; `tools/autofix.mjs --issues` only on the `rest` of `<case>/fix.json`, ≤ 20) once the desktop → mobile chain is done; a stop empties the queue · some browsers send no `Origin` on service-worker GETs → `GET /job` is accepted without Origin (read-only), everything else requires the extension's exact Origin, every refusal is logged · `bridge/src/mcp.mjs` — MCP stdio, 5 tools (`angelo_read` / `angelo_expand` / `angelo_status` / `angelo_apply` / `local_figma_use`) + 20 `note_*` · `verify.mjs` — non-regression
- **Notes** (port of Retoucher, MIT → `THIRD_PARTY_LICENSES`) — `plugin/src/notes.ts` (main thread: markers, @mentions, libraries, export) · 2nd `<script>` of `plugin/src/ui.html` (panel: list, composer, options, attachments, permission / question / plan cards, 3 connection states) · `bridge/src/notes.mjs` (storage `ANGELO_DATA`, HTTP routes without Origin `/notes` `/permissions` `/presence` `/skills` `/models` `/comments` `/notes-config`, waiting = a long poll held by the bridge, panel frames through the plugin socket) · `note_*` tools of `mcp.mjs` · `bridge/src/watch.mjs` (`npm run notes-watch`, watcher run under Monitor: one JSON line per note + the path of the Angelo read of its target (`reads/<id>.angelo`, since Monitor truncates events) when nothing is Working, presence kept, persistent `seen` in `watch-seen.json`; replaces the `note_wait` loop) · `note-line.mjs` (shared note line) · `plugin/src/write/patch.ts` (revert behind Undo, written by `apply` / `exec` / `text` with `note`) · `write/text.ts` (`note_text`, `note_fonts`) · `bridge/hooks/` (PermissionRequest + PreToolUse AskUserQuestion / ExitPlanMode → panel while a note is Working, silent otherwise; installed in `~/.claude/settings.json`, template `hooks.example.json`) · skill `skill/angelo-notes` · checks 15a–15m
- **Multi-agent** — 5 agents max: `main` (the main session) + Berta, Maximus, Nora, Rosa (background helper agents) · assignment when a note moves to Working (`pickAgent` in `notes.mjs`): a single note with nothing Working → `main`, otherwise the first free helper, `main` last; an "in order" batch = the agent of its first note; 5 busy → 409, the note stays Pending and `/notes/wait` only returns it when an agent frees up · `note_split` reserves helpers for a splittable note (`helpers`) · Figma queue `inTurn` in `server.mjs`: one plugin call at a time (FIFO), a call with `agent` also waits for a running web-to-figma build (the build's own calls have no agent and are never blocked behind it) · `figmaQueue` frame → "waiting for figma" panel · plugin: one read session per agent (`sessions`, `params.agent`, default `main`), unique sids across agents; the cursor carries the agent's name · a simple note in one call: `finish` (+ `focus`) on `local_figma_use` / `angelo_apply` → note done, picture afterwards in the background (`finishNote` in `mcp.mjs`); the watcher puts the target's tree in the event (`tree`, ≤ 1500 chars) · checks 17a–17l
- `tools/web-to-figma.mjs` — capture and build are mandatory (failure = stop, an existing frame is left intact if the capture is missing) · other steps go through `step()`: a failure is reported, listed at the end of the run, `exit 1`, and the run continues · 30 min max per step · `tools/web-to-figma-check.mjs` = these failures on a fake plugin
- On-demand tools, on a page already in Figma, patching in place: `web-audit-fix` (`web-audit` report, checks) · `web-center` (content held by padding → centered) · `web-simplify` (flattens components, tried on a clone) · `web-sync` (a doc page against its capture) · `web-font-swap` (one family for another) · `web-icons-check` (doc icons, `--fix`) · diagnostics without writing: `web-drift` (page / capture shifts per band), `web-grammar-report` (the kit grammar on frozen captures), `bench` (grammar micro-benchmark)

## Plugin socket

3 barriers, `npm run verify` checks all three, never relax them:

- Bind `127.0.0.1`: the `ws` default is `::`, reachable from the local network
- `Origin` check: the plugin iframe is sandboxed, Origin is absent or `null` · a browser always sends its real Origin, which JS cannot forge · a web Origin = a third party, refused with 403
- **A single client**: a 2nd connection is refused, close 1013 · a stolen slot would let a third party receive what the agent sends and answer with fake Figma results, consumed as truth
- HTTP `/rpc` is deliberately unrestricted: several local clients (MCP, `tools/read.mjs`) share the socket without competing for it
- `Host` header checked on HTTP and on the upgrade (127.0.0.1, localhost, [::1] only, else 403): blocks DNS rebinding · a non-loopback `ANGELO_HOST` is refused unless `ANGELO_ALLOW_LAN=1`
- `local_figma_use`: `file` is optional, refused if `figma.root.name` differs

## Execution gotchas

- Figma in the background = throttled timers (`setTimeout(50)` → 665 ms): a build exceeds the 30 s exec timeout · the cursor (`makeCursor`) then jumps to its target · keep Figma in the foreground · a font installed locally may be seen by the font agent (`:44950/figma/font-files`) yet absent from `listAvailableFontsAsync` → the list only refreshes with Figma in the foreground (`osascript -e 'tell application "Figma" to activate'`), otherwise fallback to Inter · an exec cut short = orphan cursor / rings `<agent>-*`, swept at the next cursor
- Same throttling on any wait (`loadFontAsync`, yield): wake-up at one second, sometimes much more · `H.adapt` on 3806 nodes: dry run 975 ms in the foreground / 12 s in the background, write 7.9 s foreground / 278 s background · hence fonts loaded in one go and yield on elapsed time, never on node count · writing a big section = Figma in front
- Open issue: `H.brand` in a file with no local styles takes 0.8 s or 42–57 s (125 s once) for the same file, unrelated to a prior write or to polling (4 measurements, Figma in the background) · one run did not finish in 9 min, cause not established · `adaptToFile` caps at 15 min and then keeps the site's render
- Bridge :8787 is launched by the MCP or the watcher (`bridge/src/client.mjs`) and survives sessions · it restarts itself: the hash of `server.mjs` + its imports (`bridge/src/version.mjs`) is re-read every 2 s; on a source change, as soon as nothing is running (job, staging, plugin call), the new code is loaded dry (`ANGELO_DRY=1`, a syntax error keeps the old one) then a successor takes the port (`ANGELO_TAKEOVER=1`), the plugin is closed with 1012 and reconnects by itself · `ANGELO_NO_RESTART=1` disables the takeover · an older bridge (no `version` in `/health`) is replaced by the MCP or the watcher when it is idle
- Hub: `POST /hello` `{role, version}` (mcp, watch, tool without Origin; extension = its pinned Origin) and the plugin's `hello` frame → response `{bridge: {version, pid, boot, stale}, links: {bridge, plugin, pluginStale, claude, extension}}` · a `links` frame is pushed to the plugin on every change · same states in the plugin's dot (tooltip) and the extension's badge · `/health` carries `version`, `pid`, `boot`, `stale`, `busy`, `links`
- Bridge log: `~/.angelo/bridge.log` (`ANGELO_LOG`), capped at 2 MB + `.1` (`bridge/src/log.mjs`) — job lines included; read it when an extension job fails
- Heartbeat on the plugin socket: ping every 20 s, 2 unanswered → socket closed (slot freed); a live plugin is never dislodged
- Extension: the worker keeps its `background.js` until the extension is reloaded → it compares its hash (taken at install, Cache API) with the on-disk one given by `/hello` and calls `chrome.runtime.reload()` by itself, outside a capture, then restores the panel in the tabs that had it · `content.js` and `lib/capture.js` are re-read from disk on every injection
- Figma reloads the dev plugin by itself when `plugin/dist` changes (~1 s) · the first calls after a build fail with "no read in progress" until a new `angelo_read` · there is no cancel op: stopping a build = `figma.closePlugin()` through exec, then relaunch the plugin
- Plugin panel = an activity list (≤ 6 rows, 24 px) above the 40 px bar: one row per bridge request (except `ping` / `selection`) and per job step (`status`), the window grows upward through `kind: "size"` → `resizeUpwards` (`plugin/src/code.ts`), collapsed when the list is empty · an `exec`'s label = `params.label` (`makeRpc(file)(code, label)`, `run.mjs` passes the step name), otherwise the first useful line of the code
- The panel's lightning button = contextual check of the selection: a web-to-figma frame, or a node inside one (the bridge climbs to the top-level ancestor, the selection becomes `--focus <id> --box x,y,w,h`: only that node is corrected against the same region of `page.jpg`) (name `host[/path][ · 430][ · part]` + `tests/web/<case>/capture.json` and `page.jpg`) → `check` message → bridge `webCaseOf` → `tools/web-fix.mjs` (deterministic, in-place patch) then, if gaps remain, `tools/autofix.mjs --case --issues` (headless Claude, only the `rest`, report `<case>/autofix.md`); otherwise → inside the plugin: `read` (`# warn`, single-answer fixes applied by `apply`) + `H.lint()`; the leftovers, with a single selection + bridge → `fix` message → `tools/autofix.mjs --issues` (report `tests/autofix/<id>.md`), without a bridge → listed for review (hover the status)
- A call never runs twice: `/rpc` takes a `rid` (`makeRpc` sends one, its single replay reuses it) → a resend while it runs waits for the same outcome, a later one (10 min) gets it back with `replay: true` · the MCP retries only when the connection was refused before sending · a caller that hangs up while queued is never run · queue wait capped at `ANGELO_QUEUE_MAX` (150 s)
- Exec timeout (`ANGELO_EXEC_TIMEOUT`, 30 s): the caller is answered at once "may still be running there: read before retrying", but the turn stays held until Figma answers (≤ `ANGELO_LATE_HOLD`, 120 s), so the next call never lands on top · the plugin also serializes its own work (mutex in `code.ts`, except `ping` / `selection`)
- Socket drop mid-call: pending calls wait 8 s for the panel to come back · same panel (`instance` in its `hello`) → it sends the answers it kept (60 s, 50 max) · reloaded panel → the calls fail at once "plugin reloaded during the call"
- Node ids from a caller go through `plugin/src/lookup.ts` (`nodeOf` / `nodeOrNull`): malformed id refused at once (Figma would wait 10 s), document root never returned
- If the plugin is reloaded in the middle of a build, the step's replay restarts it entirely and leaves orphan nodes (empty frames at (0,0) of the board) · do not reload the plugin during a build · read-only access to a page with instances: `findAll` crashes (`get_name` on an unreachable instance sublayer), use `findAllWithCriteria` + try around `name`
- `npm run web-to-figma-check` passes 10/10 on the fake plugin: any failure is a regression

## Panel onboarding

- First-launch guide (`plugin/src/ui.html`, `Onboarding` script): 3 steps `welcome` · `client` · `test`, state by name (`at`)
- End of the guide → `figma.clientStorage` (`onboarding.done`, `// onboarding` block of `code.ts`, which also opens the extension link) · Alt-click on Guide = replay
- Next from `welcome` skips to `test` when the bridge socket is connected: a bridge that is up means the AI already holds Angelo
- `client` step: Claude Code = a one-line `claude mcp add … npx -y angelo-mcp` · Claude Desktop = a button → `angelo.mcpb` (unpkg) · other = `npx` JSON

## `angelo-mcp` npm package

- `node npm/build.mjs [--pack]` → `npm/dist/` (not in git): `mcp.mjs` + `server.mjs` bundled side by side with esbuild, zero dependencies, no install script, `angelo.mcpb` (same bundles + MCPB 0.2 manifest, Claude Desktop's Node) · metadata in `npm/package.json`, version = the root `package.json`'s
- `node npm/smoke.mjs` → `npx` of the tarball (fresh npm cache) on port 8799: init, tools, bridge launched · does not touch the live bridge
- Outside the package: web-to-figma (`runJob` refuses if `tools/` is absent), the extension, the plugin build (tolerant reads)
- Publishing = `npm publish` from `npm/dist/`, a manual step · the Figma plugin is not yet distributed (Community)
